A Harness for World Action Model Acceleration

Equipping coding agents to develop acceleration strategies tailored to different WAMs and GPU architectures.

Le Chen1, Lixin Liu2,†, Jan Schneider1, Zeju Qiu1, Simon Guist1, Bernhard Schölkopf1, Dieter Büchler1,3

1Max Planck Institute for Intelligent Systems 2The Chinese University of Hong Kong 3Johannes Kepler University Linz

†Corresponding author

Paper Code BibTeX
  1. The bottleneck World Action Models (WAMs) leverage pretrained video foundation models for robot manipulation, but their large backbones and video-action co-prediction are expensive. Although existing acceleration techniques offer many ways to reduce this cost, selecting and composing them requires substantial engineering for each model and hardware platform.
  2. The harness We present WAMJET, an agentic harness that accelerates WAM inference by equipping coding agents with reusable optimization guidance and measurement and validation tools. The agent profiles inference, modifies targeted code, validates effects, and iteratively refines the acceleration stack as bottlenecks shift, while preserving action quality.
  3. The speedup Across six WAMs, three coding agents, and two GPU architectures, WAMJET speeds up every WAM we tested, including a 9.95× lossless speedup on LingBot-VA over its upstream implementation. Approximation and hardware-aware optimization yield additional latency reductions, with comparable success rates.

Hand-tuning every WAM does not scale

Accelerating WAM inference is not a one-time optimization. It requires a recipe that composes techniques for a specific model, hardware platform, and task, and the best recipe for one WAM may not transfer directly to another.

Manual optimization requires coordination across kernel experts, model authors, and robotics engineers, and can take days to weeks for each model-GPU pair. A coding agent alone may stop at generic fixes, such as prompt caching or CUDA graphs, leaving deeper optimization opportunities unexplored.

A bottleneck-driven loop

The agent first reduces startup cost, then profiles a single inference call and targets the bottleneck. Each candidate is validated, and each accepted change becomes the new baseline. The agent then re-profiles the updated implementation and moves on to the next bottleneck.

  • Lossless techniques first: compilation, fusion, CUDA Graphs, reuse, kernel tuning.
  • Approximate techniques only when permitted, such as quantization matched to the GPU.
  • The loop continues within the available budget, rather than stopping at the first win.

Every agent goes further with WAMJET

Our first experiment gives three coding agents the same four WAMs on an H100, with and without WAMJET, and allows only lossless changes. R1 is one round of WAMJET optimization; R2 continues for a second round and is the reported result.

  • 12 of 12 agent-WAM pairs end faster with WAMJET than the same agent without it.
  • A second round helps in every pair: R2 beats R1 all 12 times.
  • The largest gain is 9.95× on LingBot-VA with GPT-6-astra; the same agent reaches 5.51× without WAMJET.

Each kept change behind the GPT-6-astra results is in the loop replay above.

Quantization recipes follow the GPU

When approximation is permitted, the agent applies quantization on top of the lossless optimizations and selects formats natively supported by the GPU. We test DreamZero[1] and Cosmos3-Nano-Policy-DROID[5] on Hopper (H100) and Blackwell (B200).

Faster must not mean worse. On a RoboLab[6] subset of 20 tasks with 10 episodes per task, task performance remains comparable to upstream.

Configuration DreamZero Cosmos3-Nano-Policy-DROID
Upstream 25.0% 43.0%
WAMJET lossless 24.0% 47.0%
WAMJET approximate FP8 26.0% 45.5%
WAMJET approximate Blackwell formats 25.0% NVFP4 + FP8 44.5% MXFP8

Room left in an already-optimized SOTA WAM

OpenWAM[7] reports state-of-the-art results on several robot benchmarks and already incorporates several inference optimizations, such as the PyTorch compiler and velocity cache. We let WAMJET-guided GPT-6-astra optimize it on a B200 and evaluate on full LIBERO[8] and full LIBERO-plus[9].

How optimization progresses

Here is how GPT-6-astra achieved its DreamZero and OpenWAM results on a B200. Each dot is a measured trial and the step line is the best configuration kept so far. Gray is the same agent without WAMJET.

Upstream (1×) Without WAMJET WAMJET lossless WAMJET approximate Faded dots: trials that were not kept
  • Without the harness, the agent stops early: after 1.38 h on DreamZero (1.11×) and 0.62 h on OpenWAM (1.30×).
  • With WAMJET it keeps improving for hours, reaching 2.21× on DreamZero (NVFP4 + FP8) and 2.75× on OpenWAM (FP8).
  • Shared techniques, different recipes: both runs use CUDA Graphs and operator fusion, but the final optimization recipes differ between the two models.

Run WAMJET on your own WAM

To use WAMJET with your coding agent, start by installing its tools:

git clone https://github.com/liulixinkerry/WAMJET.git
cd WAMJET
python -m pip install -e '.[numerics]'
